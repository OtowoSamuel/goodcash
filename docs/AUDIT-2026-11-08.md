# GoodCash audit, 8 November 2026

Branch: `audit-20261108` (not pushed, nothing deployed). Scope: both routers, the worker, the web app, wording, UI spot checks and on-chain reconciliation.

## 1. Summary

**Solid**
- Both routers on Celo run exactly the code in this repo (bytecode compared byte for byte, metadata included).
- The one-tap router (V2) is well built: only the G$ token can call it, the payer is supplied by the token, the payout is exact, the surplus goes back to the customer, approvals are exact and reset, and stray dust cannot block it. Its owner is the GoodCash Safe (1-of-2, no modules, no guard) and it can only pause and unpause.
- Neither router holds any G$, USDm or USDT right now.
- All 60 contract tests pass, including fork tests against live Celo. All 85 worker tests and 215 app tests pass; the app suite passed 3 runs in a row.
- 11 of the 13 cash outs on-chain match a settled (or bank-paid) payout order. The other 2 are known team test transactions (see section 6).
- No customer ID details (BVN, NIN, birth date) are written to storage or logs.

**Risky, in order**
1. The original router (V1) can be blocked by anyone sending it 1 unit of a token (M1).
2. The newer router's source is not verified on the block explorer, while it is the one customers use (M2).
3. The three-step cash out still trusts the wallet's reply, like one-tap did before today's fix (M3).
4. The 1% fee has not yet been seen arriving in the Safe (M4).
5. The cause of the laptop errors is still unknown (M5).

**Must fix before more volume:** M2 (verify, a few minutes), M4 (check one real fee lands), M5 (one reproduction with logs on).
